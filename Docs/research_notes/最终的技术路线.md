# 最终技术路线：WarpX 插件化 Runtime

<!-- SPDX-License-Identifier: BSD-3-Clause -->

> 状态：**唯一准绳**（2026-11-04）。取代 `PLUGIN_ARCHITECTURE_DESIGN.md`、`PLUGIN_ARCHITECTURE_FINAL.md`、`PLUGIN_RUNTIME_ARCHITECTURE_V2.md` 作为实施依据；`SOURCE_AUDIT.md` 是本文的审计底稿。
> 选择：**路线 B（Runtime 重写）**，不是“在 WarpX 内开几个洞”。
> 一句话：**主程序是不含物理的 `SimulationRuntime`；`WarpX` 降级为标准 PIC/EM 包；插件只认命名状态 + 阶段 + 数据依赖；内核负责 AMReX 生命周期、通信、IO、调度。**

---

## 0. 结论先行

1. **主程序**：`warpx_runtime`（`SimulationRuntime`），不是 `WarpX::Evolve`。
2. **最普适的底座**：AMReX（网格/AMR/MPI/GPU/粒子容器/EB 框架/Arena/plotfile）+ 一层新的“命名状态 + 数据总线 + 阶段调度 + 插件宿主”。`WarpX` 的物理类全部下沉。
3. **插件协作**：插件之间零直接依赖、零直接调用；只通过 **DataBus** 读写命名数据，由内核在**标准阶段**内按**数据依赖拓扑排序**执行。
4. **代价**：这不是 6 个月的活。审计后的真实成本是 **16–30 人月**：先去单例（66 static、241 处 `GetInstance`）、再统一 Level 资源、再拆生命周期、最后才是调度器。
5. **当前状态**：源码审计约完成 15%；本文的实施计划以“先补审计（A0）”开头，不以“已看完源码”为前提。

## 1. 目标与不变量

### 1.1 目标

用户新增能力 = **写一个模块 + 用标准插头接上**，不改内核：

```
新场方程/场求解器（Maxwell+引力、新 stencil）
新物质模型（流体+引力、新 PIC 模型）
新材料（ε/σ/μ、相变、损耗）
新边界（PEC/PMC/自定义壁）
新源项（外场、电流源、化学反应源）
新诊断/碰撞/QED/滤波
新 AMR 策略（tagging/负载均衡）
```

### 1.2 不变量

| # | 不变量 | 说明 |
|---|---|---|
| I1 | 内核不含物理 | 内核里没有 `Efield`、`rho`、`Boris`、`Yee`；只有 `FieldKey`/`SpeciesKey`/`Stage` |
| I2 | 插件不互认 | 不持有彼此指针、不直接调用；只通过 DataBus |
| I3 | 生命周期归内核 | `Alloc/Remake/Redistribute/FillBoundary/checkpoint` 归内核；插件只声明 |
| I4 | 旧输入不破坏 | `algo.*` 等旧参数映射到内置插件名 |
| I5 | 逐位可回归 | 默认路径 = 旧实现；A/B 逐位是硬门 |
| I6 | GPU 不被抽象拖慢 | 阶段边界虚调用；kernel 内 `Array4`，零 per-cell 虚调用 |

完整底稿见 [`SOURCE_AUDIT.md`](SOURCE_AUDIT.md)。以下是不可回避的数字：

| 事实 | 数值 | 含义 |
|---|---:|---|

| `WarpX.H` | 1,811 行、254 个成员、191 个函数 | 上帝类 |

**结论**：Route B 的第一年不是写 Runtime，而是：

1. **A0 审计**：补齐 12 个子系统的状态/生命周期/数据键；
2. **A1 去单例**：66 static + 241 `GetInstance` → `RuntimeConfig`/`TimeState`/`Services` 注入；
3. **A2 Level 资源**：统一 `LevelResources`、`AllocLevelData` schema 化、`ClearLevel` 完整化；
4. **A3 生命周期拆包**：`InitData`/`Evolve`/`Finalize` 拆成阶段，`WarpX` 降为 `PicEmPackage`；
5. **A4 状态 schema**：`FieldRegistry`/`SpeciesRegistry`/`MaterialRegistry`；
6. **A5 调度器**：Stage + Handler + 数据依赖；
7. **A6 动态 regrid**：`AmrCore::regrid` + 通用 `RemakeLevel` + `on_regrid`。

## 3. 最终架构

### 3.1 主程序

```cpp
// Source/main.cpp（目标形态）
int main (int argc, char* argv[])
{
    warpx::runtime::Runtime runtime(argc, argv);   // AMReX + 输入 + PluginHost
    runtime.load_package<warpx::pic::PicEmPackage>();
    runtime.load_plugins_from_input();             // plugins.<role> = <name>
    runtime.initialize();                          // schema → resolve → on_init
    runtime.run();                                 // Scheduler
    runtime.finalize();
}
```

`Runtime` 拥有：

```
MeshSubstrate        AMReX AmrCore 包装：level/BA/DM/geom/refRatio/periodicity
StateSubstrate       FieldRegistry / SpeciesRegistry / MaterialRegistry / AuxRegistry
DataBus              命名数据 + schema + 读写权限 + 访问审计
Scheduler            Stage + Handler + 数据依赖拓扑排序 + 冲突检测
PluginHost           注册/选择/依赖注入/版本/生命周期
Services             FillBoundary/SumBoundary/Reduce/Parser/RNG/FFT/Poisson/Log/Profile/alloc_temp
IOSubstrate          schema 驱动 checkpoint/restart + plotfile/openPMD 调度
EbSubstrate          AMReX EB 几何查询 + cut-cell 数据接口（算法在插件）
```

### 3.2 内核只认什么

```cpp
using FieldKey    = std::string;   // "E_x", "rho", "phi_gravity", "mass_source"
using SpeciesKey  = std::string;   // "electron", "ion", "gas"
using MaterialKey = std::string;   // "eps", "sigma", "mu"
using ScalarKey   = std::string;   // "T_e", "phase_fraction"

struct FieldSpec { int ncomp; amrex::IntVect nodal; amrex::IntVect ngrow; bool checkpoint; std::string unit; };
struct SpeciesSpec { enum class Kind { Particles, Fluid }; Kind kind; int ncomp; std::vector<std::string> components; };
```

**内核里没有 `Efield`、没有 `rho`、没有 `Boris`、没有 `Yee`。** 这些键由 `PicEmPackage` 注册。

### 3.3 数据总线

```cpp
class DataBus {
public:
    [[nodiscard]] const amrex::MultiFab& field (FieldKey, int lev) const;
    [[nodiscard]] amrex::MultiFab&       field (FieldKey, int lev);       // 写
    [[nodiscard]] const amrex::MultiFab& material (MaterialKey, int lev) const;
    [[nodiscard]] amrex::Real            scalar (ScalarKey) const;
    [[nodiscard]] SpeciesHandle          species (SpeciesKey);           // 不透明句柄
    [[nodiscard]] const FieldSpec&       spec (FieldKey) const;
    void register_field (FieldKey, FieldSpec);
    void register_species (SpeciesKey, SpeciesSpec);
};
```

- 所有键在 `on_schema` 注册完毕；之后只读/写。
- 写权限按 handler 的 `produces` 校验；未声明写却写 → abort。
- 自定义场用 `MultiFabRegister::alloc_init(name, …, remake=true)`，`RemakeLevel` 自动重分配。
- 单位/分量在 schema 里，诊断/IO 自动生成。

### 3.4 阶段与依赖调度

内核标准阶段（物理中立）：

```
OnSchema, OnInitialize, BeforeStep, BeforeDeposit, AfterDeposit,
BeforeFieldSolve, AfterFieldSolve, BeforeParticlePush, AfterParticlePush,
BeforeDiagnostics, AfterStep, OnRegrid, OnCheckpoint, OnFinalize
// 包可定义子阶段（Collisions/Chemistry/Sources）；内核只保证标准阶段先后
```

插件声明：

```cpp
struct HandlerSpec {
    std::string name;          // "vaporization"
    Stage stage;               // AfterDeposit
    int priority = 0;
    std::vector<FieldKey>   reads_fields,  writes_fields;
    std::vector<SpeciesKey> reads_species, writes_species;
    std::vector<MaterialKey> reads_material, writes_material;
    std::vector<ScalarKey>  reads_scalars,  writes_scalars;
};
```

调度器 `resolve()`：

1. 按阶段分组；
2. 同阶段内“写 → 读”建边（A 写 X，B 读 X ⇒ A 先于 B）；
3. 拓扑排序；有环 → abort，打印环；
4. 同阶段写同键且无先后 → abort；
5. `priority` 只用于无依赖并列项，保证确定性。

**为什么不是固定钩子表**：化学可能要在碰撞前或后，气化可能要在沉积前或后；固定顺序覆盖不了。标准阶段给粗顺序，数据依赖给细顺序。

### 3.5 插件契约

```cpp
struct PluginInfo {
    const char* name;
    const char* version;
    Role role;
    std::vector<std::string> requires;   // 依赖的服务/角色
    std::vector<HandlerSpec> handlers;   // 可挂多个阶段
    int api_version = 1;
};

class IPlugin {
public:
    virtual ~IPlugin () = default;
    [[nodiscard]] virtual PluginInfo info () const = 0;
    virtual void on_schema   (SchemaBuilder&) {}
    virtual void on_init     (InitContext&)   {}
    virtual void on_stage    (StageContext&)  {}
    virtual void on_regrid   (int lev)        {}
    virtual void on_checkpoint (CheckpointWriter&) {}
    virtual void on_restart  (CheckpointReader&)   {}
    virtual void on_finalize () {}
};
```

- 没有 `WarpX&` 参数；只有 `StageContext`（DataBus + Services + Time + Geometry）。
- 不持有别的插件指针。
- 加载：编译期静态注册为主；运行期 `.so` 可选，只允许 host 侧 handler，校验 `api_version`/`WARPX_VERSION`/`sizeof(Real)`/`WARPX_DIMS`/GPU 标志。

### 3.6 标准 PIC/EM 包

```cpp
class IPhysicsPackage {
public:
    virtual void declare_schema (SchemaBuilder&) = 0;
    virtual void declare_stages (StagePlan&) = 0;
    virtual void register_plugins (PluginHost&) = 0;
};
```

`PicEmPackage` 注册 `yee`/`psatd`/`pic`/`fluid_cold`/`moment5`/`medium_tensor`/`pec`/`pml`/`full_diag` 等，声明标准显式 Strang 序列。多个包（PIC/EM + 化学 + 气化）时 `StagePlan` 合并；包之间也只通过 DataBus 交互。

## 7. 验收

1. **同一二进制 A/B 逐位**：默认路径 vs 包路径；探针 ASCII + plotfile payload 字节。
2. **跨二进制数值门**：≤1e-12；σ=0 等简单路径逐位。
3. **能力门**：`Caps` 声明不支持 AMR/coarse/EB 却在对应输入下运行 → abort。
4. **重启门**：旧 checkpoint 可读；新 schema 写出的 checkpoint 可恢复。
5. **外挂门**：一个用户 `.cpp` + `-DWarpX_EXTRA_PLUGIN_SOURCES` 能编过跑通。
6. **回归门**：P0/E3/S5/E6 + 真空 ECT + 上游 ctest。
7. **覆盖矩阵**：P0/E3/S5/E6 走 `MacroscopicEvolveE`，只覆盖 B 半步；E 分派必须用真空/ECT/上游 ctest 单独证明。
