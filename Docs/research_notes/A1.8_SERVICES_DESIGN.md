# A1.8 剩余单例：HybridPICModel 与 ElectrostaticSolvers 调研

> 结论先行：
> - **ElectrostaticSolvers 可以先做**：它只需要 2 个算法服务和 4 个“按 level 的向量”数据访问。
> - **HybridPICModel 不应作为一个模块迁移**：目标架构要求按功能拆成多个 handler，通过 `DataBus` 的命名状态交互；A1.8 不做它，A3 建 `HybridPackage` 时拆。
> - 下一步顺序：**ES 先做并加算例；Hybrid 在 A3 拆分，不在 A1.8 硬迁移**。

## 1. 调研方法

逐行检查：

```
Source/FieldSolver/ElectrostaticSolvers/*.cpp
Source/FieldSolver/FiniteDifferenceSolver/HybridPICModel/*.cpp
Source/WarpX.H
Source/Runtime/HostServices.H
Source/Runtime/RuntimeData.H
```

对每个 `WarpX::GetInstance()` 记录：

- 用了 `warpx.` 的哪些成员；
- 该成员是纯数据、算法、还是带状态的内核对象；
- 现有 `RuntimeData/HostServices` 是否覆盖；
- 迁移后由谁保证时序。

## 2. HybridPICModel 的真实依赖

29 处 `GetInstance()`，按用途分类：

### 2.1 纯数据（可直接进 RuntimeData）

| 成员 | 次数 | 现有接口 |
|---|---:|---|
| `warpx.finestLevel()` | 8 | `RuntimeData::finestLevel()` |
| `warpx.Geom(lev)` | 10+ | `data().geom(lev)` |
| `warpx.m_fields` | 20+ | `data().fields()` |
| `warpx.gett_new/gett_old/getdt` | 6 | `data().t_new/t_old/dt` |
| `warpx.GetPartContainer()` | 8 | `data().particles()` |

这些不是问题。

### 2.2 场边界/滤波（需要 kernel service）

| 调用 | 语义 | 为什么不能直接替换 |
|---|---|---|
| `warpx.ApplyEfieldBoundary(lev, patch, time)` | E 场边界 | 依赖 patch/BC/PML 内部状态 |
| `warpx.ApplyElectronPressureBoundary(lev, PatchType::fine)` | 电子压力边界 | 同上 |
| `warpx.ApplyFieldBoundaryOnAxis(...)` | RZ 轴边界 | 需要几何/轴特判 |
| `warpx.FillBoundaryE/B(ng, nodal_sync)` | 同步场 guard | 与 moving window/PML 顺序耦合 |
| `warpx.ApplyFilterMF(Ve, lev, idir)` | 滤波 | 依赖 filter 状态与多级字段 |

**建议接口**：不要把这些拆成 5 个 `HostServices` 方法，而是定义 **`HybridPICServices`**：

```cpp
class HybridPICServices {
public:
    virtual void applyEfieldBoundary(int lev, PatchType, Real time) = 0;
    virtual void applyElectronPressureBoundary(int lev) = 0;
    virtual void applyFieldBoundaryOnAxis(int lev) = 0;
    virtual void fillBoundaryE(int lev, IntVect ng, bool nodal_sync) = 0;
    virtual void fillBoundaryB(int lev, IntVect ng, bool nodal_sync) = 0;
    virtual void applyFilter(const MultiLevelVectorField&, int lev, int idir) = 0;
};
```

### 2.3 求解器内部对象（不可进 HostServices 的“纯函数”）

| 调用 | 语义 | 风险 |
|---|---|---|
| `warpx.get_pointer_fdtd_solver_fp(lev)` | 取 FDTD solver | 返回内部对象，插件会绕过接口 |
| `solver->CalculateCurrentAmpere(...)` | Ampere 电流 | 依赖 solver 的 stencil/PML |
| `solver->HybridPICSolveE(...)` | 混合 E 推进 | 依赖 solver 状态 |
| `warpx.ComputeExternalFieldOnGridUsingParser(...)` | 外部场 parser | 依赖 parser/EB 更新标志 |
| `warpx.GetEBUpdateEFlag_fp()` | EB 更新标志 | 依赖 EB 状态 |

**建议**：这些不是 A1.8 的“去单例”问题，而是 **A3 的 Handler 内部实现**：

- `HybridPICModel` 本身应成为 `PicEmPackage` 的一个 composite handler；
- 上述调用是 composite handler 内部的 kernel service，不暴露给普通插件；
- A1.8 不要为了删 `GetInstance()` 而把 FDTD solver 指针塞进 `HostServices`，否则等于把上帝对象换了个名字。

### 2.4 QDSMC / 粒子状态

```cpp
m_qdsmc_pc = std::make_unique<QdsmcParticleContainer>(&warpx);
warpx.GetPartContainer()
QDSMCFill...
```

Hybrid 模型持有 `QdsmcParticleContainer`，说明它**同时产生场和粒子状态**。这正是审计 D5/§5 指出的“求解器持粒子态”。

**建议**：A3 用 `HandlerSpec` 声明：

```
reads_fields: hybrid_*
writes_fields: hybrid_*
reads_species: qdsmc
writes_species: qdsmc
checkpoint_fields: ...
```

A1.8 不处理。

### 2.5 控制/诊断

```cpp
warpx.Verbose()
warpx.EvolveB(dt, subcycling_half, t_old)
```

`EvolveB` 是推进编排，不是诊断数据；只能在 A3 的 stage 内出现。


## 2.6 修正：Hybrid 不是单一 composite handler

前一版把 Hybrid 写成“一个 composite handler”，那只是一种**过渡容器**的说法，和目标架构冲突。正确做法是**按功能拆成多个模块/handler**，它们之间只通过 `DataBus` 的命名状态交互，不共享 `HybridPICModel` 对象。

### 建议的拆分

| 模块 | 读 | 写 | 阶段 |
|---|---|---|---|
| `HybridExternalFields` | `B`, `B_external` | `J_external`, `E_external` | `BeforeFieldSolve` |
| `HybridAmpereCurrent` | `B` | `J_plasma` | `FieldSolve` |
| `HybridOhmSolver` | `B`, `J_plasma`, `J_external`, `rho`, `Te`, `eta_overlay` | `E` | `FieldSolve` |
| `ElectronPressureClosure` | `rho`, `Ke`, `qdsmc_weights` | `Te`, `Pe` | `FieldSolve` |
| `ElectronEnergyTransport` | `Te`, `rho`, `Ve` | `Ke`, `qdsmc_weights`, `qdsmc` species | `FieldSolve` |
| `HybridBoundaryFilter` | `E`, `B`, `Te`, `Pe`, `Ve` | same fields | `AfterFieldSolve` |

`HybridPICModel` 最终只保留为 **`HybridPackage` 的注册/配置入口**：

```cpp
class HybridPackage {
    void register_handlers(PluginHost& host);
    void register_schema(DataBus& bus);
};
```

### DataBus 键（示例）

```text
E_x, E_y, E_z
B_x, B_y, B_z
J_plasma_x, J_plasma_y, J_plasma_z
J_external_x, J_external_y, J_external_z
rho
Te, Pe, Ke
Ve_x, Ve_y, Ve_z
qdsmc_weights
eta_overlay
```

### 依赖顺序

```text
HybridExternalFields
  -> HybridAmpereCurrent
  -> HybridOhmSolver
  -> ElectronPressureClosure
  -> ElectronEnergyTransport
  -> HybridBoundaryFilter
```

由 `HandlerSpec.reads_fields/writes_fields` 的拓扑排序保证，而不是 `HybridPICModel` 内部函数调用顺序。

### 这样做的代价

- `HybridOhmSolver` 需要 `IFieldInternalAccess`（FDTD stencil/PML 内部状态）作为 host service；
- `ElectronEnergyTransport` 需要 `SpeciesHandle` 管理 QDSMC 粒子容器；
- 这两项是 A3 的内容，不是 A1.8 的“去单例”。

因此 A1.8 **不迁移 HybridPICModel**；A3 新建 `HybridPackage` 并按上表拆分。

## 4. 建议的接口扩展

### 4.1 RuntimeData 增加“按 level 的向量”

```cpp
[[nodiscard]] virtual const amrex::Vector<amrex::Geometry>& geomAll() const = 0;
[[nodiscard]] virtual const amrex::Vector<amrex::BoxArray>& boxArrayAll() const = 0;
[[nodiscard]] virtual const amrex::Vector<amrex::DistributionMapping>& distributionMapAll() const = 0;
[[nodiscard]] virtual const amrex::Vector<amrex::IntVect>& refRatioAll() const = 0;
```

适配器直接返回 `m_warpx.Geom()` / `boxArray()` / `DistributionMap()` / `refRatio()`。

### 4.2 HostServices 增加 ES 算法

```cpp
virtual void syncRho(
    const ablastr::fields::MultiLevelScalarField& rho_fp,
    const ablastr::fields::MultiLevelScalarField& rho_cp,
    const ablastr::fields::MultiLevelScalarField& rho_buffer) = 0;

virtual void finalizeRhoOnLevel(int lev, amrex::MultiFab* rho, PatchType) = 0;
```

适配器分别调 `m_warpx.SyncRho(...)` 与 `m_warpx.FinalizeRhoOnLevel(...)`。

### 4.3 Hybrid 的接口放 A3

不要在 A1.8 新增：

```cpp
getPointerFdtdSolver()
applyEfieldBoundary()
calculateCurrentAmpere()
```

这些会把 solver 内部对象暴露成公共 API，和“插件只认内核接口”冲突；应在 `PicEmPackage` 的 composite handler 内部完成。

## 5. 迁移顺序与验收

### 第一步：ES（低风险）

1. `RuntimeData` 加 4 个 `*All()`；
2. `HostServices` 加 `syncRho/finalizeRhoOnLevel`；
3. 改 4 个 ES 文件；
4. 新增 2D 静电算例：
   - `algo.maxwell_solver = none`
   - `warpx.do_electrostatic = labframe`
   - 均匀电荷/导体边界，断言 phi/Ex；
5. 默认 + FFT 回归。

### 第二步：Hybrid（A3）

1. 定义 `HybridPICServices` / `HandlerSpec`；
2. 把 FDTD/边界/滤波/QDSMC 收进 composite handler；
3. 加 2D Hybrid 算例（已有 Hybrid 输入）；
4. 再删 `HybridPICModel` 内的 `GetInstance()`。

## 6. 结论

- **A1.8 现在应该做 ES，不应做 Hybrid。**
- Hybrid 的 29 处不是 29 个独立替换；目标是把它们拆成 6 个模块，用 `DataBus` 的命名状态交互，而不是保留一个 `HybridPICModel` 上帝对象。
- A1.8 若硬迁移，只会把上帝对象换个名字；Hybrid 拆分属于 A3 的 `HybridPackage`。
- ES 做完后，A1.8 剩下的主要就是 `Particles`/`Diagnostics` 少量局部点，以及 `m_instance` 本体的最终移除。
