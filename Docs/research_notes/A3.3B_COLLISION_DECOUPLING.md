# A3.3b 碰撞子系统解耦调研

> 结论：`CollisionHandler` 本身很薄，真正的耦合在 **各 collision model 直接使用
> `MultiParticleContainer*`**。不能只改 handler 构造参数。

## 1. 调用链

```text
MultiParticleContainer::doCollisions
  -> CollisionHandler::doCollisions(step,time,dt,this)
    -> collision->doCollisions(time,dt,mypc)
```

`CollisionHandler` 构造时接收 `const MultiParticleContainer*`，但 `doCollisions`
仍然把 `MultiParticleContainer*` 传给每个 model。

## 2. model 对 mypc 的依赖统计

| 方法 | 次数 | 用途 |
|---|---:|---|
| `GetParticleContainerFromName` | 39 | 取物种容器 |
| `config()` | 10 | 配置 |
| `data()` | 6 | RuntimeData |
| `nSpecies()` | 2 | 物种数 |
| `TransformMomentumToCurvilinear` | 2 | RZ 动量变换 |
| `GetParticleContainer` | 2 | 按索引取容器 |
| `GetSpeciesNames` | 1 | 物种名 |
| `GenerateGlobalDebyeLength` | 1 | 全局德拜长度 |
| `CalculateNuei` | 1 | 碰撞频率 |

`config()`/`data()` 已经有替代；主要问题是 **39 处直接取粒子容器**。

## 4. 不能做的改法

```cpp
class CollisionHandlerWrapper : public IHandler {
    CollisionHandler* m_handler;  // 仍持有 mypc
};
```

这只是把 `CollisionHandler` 藏进插件，没有解决 39 处容器访问。

## 5. 可行拆分

### 第 1 步：CollisionSpecies 表

```cpp
class CollisionSpeciesTable {
public:
    [[nodiscard]] WarpXParticleContainer* get (const std::string& name) const;
    [[nodiscard]] int size () const;
    [[nodiscard]] std::vector<std::string> names () const;
};
```

`CollisionSpeciesTable` 只在碰撞包内部可见，不进 `IHandler` 公共接口。

### 第 2 步：CollisionHandler 去容器

```cpp
CollisionHandler(const CollisionSpeciesTable& species);
void doCollisions(int step, Real time, Real dt);
```

删除 `MultiParticleContainer*` 参数。

### 第 3 步：model 构造参数

各 model 改为接收：

```cpp
CollisionSpeciesTable species;
RuntimeConfig config;
RuntimeData data;
```

替换 `mypc->GetParticleContainerFromName(name)` 为 `species.get(name)`。

### 第 4 步：RZ 变换 / 全局德拜长度

`TransformMomentumToCurvilinear`、`GenerateGlobalDebyeLength` 移到
`HostServices`，由包调用。

### 第 5 步：CollisionPackage 执行 handler

```cpp
class CollisionHandlerAdapter : public IHandler {
    CollisionHandler m_handler;  // 只依赖 CollisionSpeciesTable
};
```

## 6. 验收

- `Source/Particles/Collision` 不 include `MultiParticleContainer.H`；
- `rg "mypc->" Source/Particles/Collision` 为 0；
- `test_2d_collision_xz` 数值保持 `4.66e-4`；
- `CollisionHandler` 不再接收 `MultiParticleContainer*`。

## 7. 当前决定

先做 **CollisionSpeciesTable**，不直接改 8 个 model。

原因：39 处容器访问是主要工作量，先集中到一张表，后续逐个 model 替换时只改一处访问方式。

## 8. 风险

- `WarpXParticleContainer*` 仍会出现在碰撞包内部，但不出现在 `IHandler` 接口；
- `TransformMomentumToCurvilinear` 涉及 RZ 状态，必须留在 HostServices；
- `GenerateGlobalDebyeLength` 依赖全局物种，不能简单塞进单个 handle。

## 9. 所有权收口（2026-11-06）

`MultiParticleContainer` 已彻底移除：

```cpp
std::unique_ptr<CollisionHandler> collisionhandler;
CollisionHandler* m_collision_handler_external;
setCollisionHandler
activeCollisionHandler
doCollisions
```

`AllocData` 不再创建/调用碰撞 handler。

新的所有权：

```
Runtime::m_collision_handler         unique_ptr，主路径拥有
WarpX::m_collision_handler           非拥有指针，供 fallback/adapter
WarpX::m_legacy_collision_handler    仅 Python/无 Runtime 时懒创建
WarpX::m_legacy_data/host/config      legacy 适配器
MultiParticleContainer               无碰撞成员
```

`Runtime::initialize()` 在 `InitData()` 之后调用一次：

```cpp
m_collision_handler->AllocData();
```

`WarpX::RunCollisionStage()`：

1. PluginHost 有 `Stage::Collisions` handler：走 adapter；
2. 否则使用 `m_collision_handler`；
3. 仍为空时懒创建 legacy handler。

## 11. 尚未完成

`CollisionHandler` 内部仍用 `CollisionSpeciesTable`，不是公开 `SpeciesHandle`。
A3.3b 的“插件只读 SpeciesHandle”还未完成，不能宣称 A3.3b 全部关闭。

## 12. SpeciesHandle 元数据（增量）

`SpeciesHandle` 增加：

```cpp
amrex::Real charge () const;
amrex::Real mass () const;
```

实现来自 package 内部 `WarpXParticleContainer`，但 handler 仍只看到这两个只读值。

测试：

```
runtime_e_2 / runtime_es_2 / runtime_lb_2 / psatd 模式
SpeciesHandle charge == -q_e
SpeciesHandle mass   == m_e
```

通过。

这仍**不满足** A3.3b 的“插件只读 SpeciesHandle”全部要求：
碰撞 model 还需要 tile 访问、粒子复制/删除/沉积。下一步必须先定义 package-private
`CollisionSpeciesView`，再逐个 model 迁移。

## 13. CollisionSpeciesView 首个 model 迁移

新增 package-private：

```cpp
class CollisionSpeciesView {
    const SpeciesHandle& handle() const;
    WarpXParticleContainer& container() const;
};
```

`CollisionSpeciesTable::view(name)` 返回 view，不把裸指针直接暴露给新代码。

`PulsedDecay` 已从：

```cpp
auto& parent = *m_species.get(name);
```

迁移为：

```cpp
const auto parent_view = m_species.view(name);
auto& parent = parent_view.container();
```

验收：

```
runtime 5/5 PASS
test_2d_collision_xz PASS
```

这仍是增量：其余碰撞 model 继续使用 `get()` 裸指针，A3.3b 尚未关闭。
