# A3.3b 执行 handler 的状态边界

> 结论：`PicEmPackage` 目前只能声明 spec，不能注册执行 handler。
> 执行 `pic_push` 至少需要 **SpeciesHandle** 和 **回调/时间服务**，
> 这些还不存在；直接包 `WarpX*` 会违反模块判据。

## 1. `pic_push` 实际依赖

`OneStep_PushParticles` 内部：

```
mypc->doCollisions(step, time, dt)
PushParticlesandDeposit(time, skip_deposition, position, momentum)
ExecutePythonCallback("beforedeposition"/"beforecollisions"/...)
m_collisions_split_momentum_push
```

| 依赖 | 当前来源 | 目标 |
|---|---|---|
| species 集合 | `MultiParticleContainer& mypc` | `DataBus::species()` + `SpeciesHandle` |
| collisions | `mypc->doCollisions` | `HostServices::collisions()` 或独立模块 |
| push | `WarpX::PushParticlesandDeposit` | `HostServices::pushParticlesAndDeposit` |
| callbacks | `WarpX::ExecutePythonCallback` | `HostServices::callbacks()` |
| split flag | `WarpX::m_collisions_split_momentum_push` | `RuntimeConfig` |
| time/dt/step | 参数 | `StageContext` |

## 2. `pic_finalize_deposition` 依赖

```
SyncCurrentAndRho
FinalizeRho
FinalizeJ
MomentFluidSolver
```

这些已经大多在 `HostServices` 有对应物：

```
syncRho
finalizeRhoOnLevel
syncCurrent
```

但 `MomentFluidSolver` 不属于 HostServices，需要决定它是独立模块还是服务。

## 3. `pic_field_solve` 依赖

```
do_pml
electromagnetic_solver_id
dt
guard_cells
PSATD/Yee 选择
```

`guard_cells` 仍在 `WarpX`，尚未进 `RuntimeData`。这是 A3.3b3 的前置。

## 4. 不能做的做法

```cpp
class WarpXHandler : public IHandler {
    WarpX* warpx;  // 错
    void apply(...) { warpx->OneStep_...(); }
};
```

这只是把 `WarpX` 藏进插件，模块之间仍然通过上帝对象耦合。

## 5. 分步

### A3.3b2 SpeciesHandle

- `SpeciesSpec`（name、charge、mass、kind）；
- `DataBus::register_species`；
- 不透明 `SpeciesHandle`：`numberOfParticles`、`momentum`、`position`、`weight`；
- 底层仍由 `WarpXParticleContainer` 实现，但类型不出现在 handler 接口。

### A3.3b3 push/finalize 服务化

- `HostServices::pushParticlesAndDeposit(...)`;
- `HostServices::callbacks()`;
- `RuntimeConfig::collisions_split_momentum_push()`;
- 然后才写 `PicPushHandler`。

### A3.3b4 field solve

- `guard_cells` 进 `RuntimeData`；
- PML/field solver 通过 `HostServices`；
- `PicFieldSolveHandler`。

## 6. 验收

- handler 源文件不 include `WarpX.H`；
- `rg "WarpX\\*|WarpX&" Source/Runtime/Handlers` 为 0；
- `PicEmPackage` 注册执行 handler 后，`runtime` 测试仍按 `StagePlan` 顺序执行；
- Langmuir 数值不变。

## 7. 当前决定

A3.3b2 先做 `SpeciesHandle`，不做 `PicPushHandler`。
没有 SpeciesHandle 的 push handler 只能持有 `WarpX*`，不符合目标。
