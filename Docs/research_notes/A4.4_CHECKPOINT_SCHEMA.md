# A4.4 checkpoint schema 进展

## 已完成

1. `FieldRegistry::checkpointNames()` 返回所有 `checkpoint=true` 的字段。
2. `AllocLevelField` 标记：
   - `Efield_fp_x/y/z`
   - `Bfield_fp_x/y/z`
   - `current_fp_x/y/z`
   - `E_old_x/y/z`
3. `RuntimeData::fieldRegistry()` 暴露给诊断层。
4. checkpoint 写出增加**附加**文件：

```text
<checkpoint>/field_schema.txt
```

内容为注册表中 checkpoint 字段名。

## 兼容性

- 旧 checkpoint 没有 `field_schema.txt`，读取路径不变；
- 新 checkpoint 多一个文本文件，旧 reader 忽略；
- `test_2d_ionization_lab_restart` run + analysis 通过。

## schema 驱动写出（已完成）

`FlushFormatCheckpoint` 现在遍历：

```cpp
data().fieldRegistry().checkpointNames()
```

并通过 key -> `(FieldType, Direction, legacy filename)` 映射写出。
文件名与旧格式保持一致（`Ex_fp`、`jx_fp`、`Ex_old` 等），
`WarpXHeader` 未改，因此旧 checkpoint 仍可读。

原先硬编码的字段块已删除。

```text
Ex_fp / Ey_fp / Ez_fp
E_old
E_avg/B_avg
jx_fp ...
cp 层
PML
```

`field_schema.txt` 尚未驱动写出或读取，只是 additive manifest。

剩余：

1. `WarpXHeader` 自身的版本化/双读（当前格式未变，旧文件可读）；
2. A4.5 重启逐位门。
