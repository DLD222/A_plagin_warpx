# A2.1 LevelResources 调研与设计

> 目标：把“每个 level 的资源”从 `WarpX` 散落成员收进一个 **单一所有者** 的登记表，
> 使 `AllocLevelData / ClearLevel / RemakeLevel` 只操作 `LevelResources`。
>
> 本文只做所有权调研与设计；代码从 A2.1a 开始。

## 1. 当前按 level 的资源

以 `Source/WarpX.H` 为准：

| 资源 | 当前成员 | 当前所有者 | 生命周期 |
|---|---|---|---|
| 场 | `m_fields`（`MultiFabRegister`） | WarpX | `AllocLevelMFs` 分配，`clear_level` 清 |
| 场工厂 | `m_field_factory` | WarpX | `AllocLevelData` 建，`ClearLevel` 未清 |
| EB 工厂 | 包含在 `m_field_factory` 内 | 同上 | 同上 |
| dotMask | `Efield_dotMask/Bfield_dotMask/Afield_dotMask/phi_dotMask` | WarpX（mutable 缓存） | 按需建，`ClearLevel` reset |
| PML | `pml` | WarpX | `InitData` 建，`ClearLevel` 未清 |
| borrowing | `m_borrowing` | WarpX | `AllocLevelData` |
| costs | `costs` | WarpX | `AllocLevelData`/LB |
| LB efficiency | `load_balance_efficiency` | WarpX | `ClearLevel` 置 -1 |
| accelerator lattice | `m_accelerator_lattice` | WarpX | Init |
| spectral solver | `spectral_solver_fp/cp` | WarpX | PSATD `InitData`，`ClearLevel` reset |
| 粒子边界缓冲 | `m_particle_boundary_buffer` | WarpX | 全局，不是 per-level |

## 2. 关键事实

1. **场已经有唯一所有者**：`MultiFabRegister`。不能再建一个场 owner，否则违反 D1。
2. `m_field_factory` 目前在 `AllocLevelData` 里重建，但 `ClearLevel` 没有 reset；这是生命周期漏洞。
3. dotMask 是“按需缓存”，不是独立物理状态；应由 LevelResources 作为 **缓存** 管理，并可从 fields 重新生成。
4. PML 是 per-level 对象，但 `ClearLevel` 没清；多级 regrid 时会残留。
5. costs/load_balance 是 per-level 标量/数组，适合放进 `LevelStorage`。
6. `spectral_solver_fp/cp` 只在 PSATD 下存在，属于“可选资源”，不能强行放进所有 level。
7. `m_particle_boundary_buffer` 是全局的，**不要**塞进 per-level。

## 3. 目标结构

```cpp
namespace warpx::runtime {

struct LevelStorage {
    int lev = -1;

    //! 场仍然由 MultiFabRegister 唯一拥有；这里只是 level 句柄。
    //! 不复制、不拥有 MultiFab。
    ablastr::fields::MultiFabRegister* fields = nullptr;

    std::unique_ptr<amrex::FabFactory<amrex::FArrayBox>> field_factory;

    //! 可选 PML（只有开 PML 时非空）
    std::unique_ptr<PML> pml;

    //! 可选 spectral solver（只有 PSATD）
    std::unique_ptr<SpectralSolver> spectral_solver_fp;
    std::unique_ptr<SpectralSolver> spectral_solver_cp;

    //! per-level 辅助数据
    std::array<std::unique_ptr<amrex::LayoutData<FaceInfoBox>>, 3> borrowing;
    std::unique_ptr<amrex::LayoutData<amrex::Real>> costs;
    amrex::Real load_balance_efficiency = -1;

    //! 可选加速器晶格
    std::unique_ptr<AcceleratorLattice> accelerator_lattice;

    //! 按需缓存，不是场 owner
    mutable std::array<std::unique_ptr<amrex::iMultiFab>, 3> Efield_dotMask;
    mutable std::array<std::unique_ptr<amrex::iMultiFab>, 3> Bfield_dotMask;
    mutable std::array<std::unique_ptr<amrex::iMultiFab>, 3> Afield_dotMask;
    mutable std::unique_ptr<amrex::iMultiFab> phi_dotMask;
};

class LevelResources {
public:
    explicit LevelResources(int nlevs);

    void resize(int nlevs);
    [[nodiscard]] int size() const;

    [[nodiscard]] LevelStorage& level(int lev);
    [[nodiscard]] const LevelStorage& level(int lev) const;

    //! 清掉一个 level 的所有非场资源；场由调用方 clear_level。
    void clear(int lev);

    //! 记住“场 register”指针，不拥有它。
    void bind_fields(ablastr::fields::MultiFabRegister& fields);

private:
    amrex::Vector<LevelStorage> m_levels;
};

}
```

### 3.1 所有权规则

- `LevelResources` **不拥有** `MultiFabRegister`；
- `field_factory/pml/spectral/borrowing/costs/lattice` 由 `LevelStorage` 独占；
- dotMask 是缓存，`clear()` 必须 reset；
- 不允许外部再持有这些 `unique_ptr` 的副本。

## 4. 迁移步骤

### A2.1a：空壳 + 绑定

- 新增 `LevelResources.H/.cpp`；
- `WarpX` 增加成员 `LevelResources m_levels;`；
- `bind_fields(m_fields)`；
- 不改现有成员，先建立“第二本账”用于断言一致性（测试：level 数、clear 次数）。

### A2.1b：field_factory 迁移

- `m_field_factory` 改为 `m_levels.level(lev).field_factory`；
- `ClearLevel` reset；
- 验证 EB/PML/MLMG 路径。

### A2.1c：PML / borrowing / costs / lattice

逐个迁移，每次一个 PR/提交，保持 build+smoke。

### A2.1d：dotMask 缓存迁移

- 从 `mutable` 成员改为 `LevelStorage`；
- `ClearLevel` reset；
- 验证 `get_dotMask` 在 regrid 后不悬空。

### A2.1e：spectral solver

- PSATD 路径迁移；
- 非 PSATD 保持空。

## 5. 验收

- `ClearLevel` 后，`m_field_factory/pml/borrowing/costs/dotMask` 全部为空；
- 多层/EB/PML/PSATD/LB 回归；
- ASAN 下多次 regrid 无 leak/use-after-free；
- `LevelResources` 是唯一可以 resize/clear 这些成员的地方；
- 场仍由 `MultiFabRegister` 唯一拥有（无第二次 alloc）。

## 6. 为什么不能一次做完

- `m_field_factory` 被 `getFieldFactory`、EB、MLMG、PML 多处引用；
- PML 构造依赖大量 WarpX 状态；
- spectral solver 只在 FFT 构建存在；
- dotMask 是 mutable 缓存，和诊断/边界时序有关。

一次替换会同时触发生命周期、EB、PML、PSATD 四条路径，无法可靠验收。按 A2.1a–e 分步，每步都能 build+smoke。
