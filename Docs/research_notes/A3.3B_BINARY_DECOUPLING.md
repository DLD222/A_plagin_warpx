# A3.3b BinaryCollision 解耦调研

> 结论：`BinaryCollision` 不是单个类，而是一条 **functor 构造链**。
> 只改 `BinaryCollision` 构造参数会在 template 实例化时全部报错。
> 必须按 functor 逐个改，最后再改 `BinaryCollision`。

## 1. 当前构造链

```text
CollisionHandler
  -> BinaryCollision<CollisionFunctor, CopyTransformFunctor>(name, mypc)
       -> BinaryCollisionUtils::get_collision_type(name, mypc)
       -> CollisionFunctor(name, mypc, isSameSpecies)
       -> CopyTransformFunctor(name, mypc)
```

`doCollisions` 里还会把 `mypc` 传给：

```text
CollisionFunctor.operator()(..., mypc)
CopyTransformFunctor(..., mypc)
```

## 2. 涉及文件

| 文件 | 当前 mypc 用法 |
|---|---|
| `BinaryCollisionUtils.H/.cpp` | 3 个函数，`GetParticleContainerFromName` |
| `BinaryCollision.H` | 构造、doCollisions |
| `Coulomb/PairWiseCoulombCollisionFunc.H` | 构造参数，当前未使用 |
| `DSMC/DSMCFunc.H/.cpp` | `operator()` 参数，5 处物种查找 |
| `DSMC/SplitAndScatterFunc.H/.cpp` | 构造参数 |
| `NuclearFusion/NuclearFusionFunc.H` | 构造参数、operator |
| `Bremsstrahlung/BremsstrahlungFunc.H/.cpp` | 构造参数 |
| `Bremsstrahlung/PhotonCreationFunc.H/.cpp` | 构造参数 |
| `ParticleCreationFunc.H/.cpp` | 构造参数 |
| `LinearBreitWheeler/LinearBreitWheelerCollisionFunc.H` | 参数标记为 unused |
| `LinearCompton/LinearComptonCollisionFunc.H` | 参数标记为 unused |

## 3. 分步

### A3.3b8f1 BinaryCollisionUtils

改签名：

```cpp
CollisionType get_collision_type(const std::string&, const CollisionSpeciesTable&);
NuclearFusionType get_nuclear_fusion_type(const std::string&, const CollisionSpeciesTable&);
```

全部 `mypc->GetParticleContainerFromName` 换 `*table.get`。

### A3.3b8f2 无状态 functor

`PairWiseCoulombCollisionFunc`、`LinearBreitWheeler`、`LinearCompton` 构造参数改为 table（或删除未用参数）。

### A3.3b8f3 有状态 functor

`ParticleCreationFunc`、`PhotonCreationFunc`、`BremsstrahlungFunc`、`SplitAndScatterFunc`：

- 构造参数改 table；
- 内部 `mypc->GetParticleContainerFromName` 换 `table.get`。

### A3.3b8f4 DSMC/NuclearFusion

`DSMCFunc::operator()` 和 `NuclearFusionFunc` 的 operator 参数改 table；
`BinaryCollision::doCollisions` 把 table 传下去。

### A3.3b8f5 BinaryCollision

最后改：

```cpp
BinaryCollision(const std::string&, const CollisionSpeciesTable&);
```

删除 `mypc` 参数。

## 4. 验收

- `Source/Particles/Collision/BinaryCollision` 不 include `MultiParticleContainer.H`；
- `rg "mypc->" Source/Particles/Collision/BinaryCollision` 为 0；
- `test_2d_collision_xz` 保持 `4.66e-4`；
- `test_2d_collision_xz_global_debye` 通过（global debye 路径）；
- 2D DSMC/核聚变输入若存在，单独跑。

## 5. 风险

- `NuclearFusionFunc` 还使用 `FieldType::global_debye_length`，需要 `RuntimeData`；
- `DSMCFunc` 有 GPU kernel 参数，改签名要保证 `AMREX_GPU_DEVICE` 捕获仍合法；
- `ParticleCreationFunc` 有模板分支，改动可能触发未实例化路径。

## 6. 当前决定

不在一步里同时改 8 个 functor。先做 A3.3b8f1（Utils），再逐个 functor，每次 build+碰撞回归。

## 7. 与 Hybrid 的顺序

`HybridResistiveDrag` 依赖 `HybridPICModel`，优先级低于 BinaryCollision；
先完成 BinaryCollision，再定义 Hybrid 服务。
