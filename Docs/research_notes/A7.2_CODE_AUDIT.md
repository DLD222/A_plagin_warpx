## 2. 已修正

### LevelResources

`LevelResources` 持有：

```text
AcceleratorLattice
PML
EB
```

它属于 WarpX level 状态，不属于 Core。

已移动：

```text
Core/Runtime/LevelResources.*
  -> Plugins/PicEm/RuntimeBridge/Runtime/
```

### WarpXIO / FieldIO

它们实现 WarpX 状态 IO，不属于 Diagnostics，也不属于 PicEm 粒子模块。

当前移到：

```text
Plugins/Diagnostics/
```

原因：

```text
WarpXIO 需要 MultiDiagnostics/ReducedDiags
它是 WarpX 与 Diagnostics 的交接层
```

这样可以保证：

```text
PicEm -> Diagnostics = 0
```

但代价是 Diagnostics 继续依赖 PicEm。

## 3. 接口审计

### IDiagnosticsService

优点：

```text
PicEm 只持接口
不再 include Diagnostics
```

问题：

```text
包含 diagName/diagTlab 等展示型方法
接口偏宽
```

### IParticleContainerAccess

问题：

```text
继承 ISpeciesMetadata
```

把“访问”和“元数据”合成一个接口。

优点：

```text
Diagnostics 一个引用即可读 species 名称与容器
```

缺点：

```text
语义不单一
```

后续可退回组合：

```cpp
metadata()
containers()
```

### IParticleContainer::Base

已经成为 Diagnostics 的粒子缓冲基类。

但 `NumRealComps/HasRealComp/GetRealCompIndex` 仍是
AMReX 具体方法包装，不是真正抽象。
